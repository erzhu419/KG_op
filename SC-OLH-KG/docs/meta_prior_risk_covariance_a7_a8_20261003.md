**当前判断：** A3-A7 的加法修正尚未形成可推广的风险适配。A8 显示，在同一正确支持和同一总方差下，重新分配方差在四类结构先验任务中有正的名义配对区间；高频风险有 15/16 种子优于添加。风险方向辨识和源协方差适配都值得解决，不能只增加残差函数数量。

下一步仍以源 meta-prior 为起点，让目标风险标签学习向哪个公开函数族、以多大比例重分配方差；对函数族和比例平均，避免硬选。六族直接来自现有字典，含线性、平方、低频正弦/余弦、两两交互及高频正弦；不提供真实支持。总函数方差、截距与 f/g 模型保留，先做同一旧 cohort 的留出验证，见 [`A9 plan`](../performance/meta_prior_risk_family_reweighting_plan.json)。本轮未运行 A9。

**局限：** A8 使用真实支持，是非部署机制对照；重分配既移除无关方向，也改变真实支持内的相对方差，不能把收益全归因于前者。A7 与 oracle 的差异还包含方向/秩先验的不确定性，不能作纯支持消融。shared/52 和 separate-risk/61 的重分配分数分别下降 0.02160、0.03297，仍未修复；没有推荐收益证据。区间为未校正多组比较的配对种子 bootstrap，全部结果来自同一开发 cohort，不能当独立确认。

A7 第一条路径 0.40 CPU 秒，预估全批 63.36 秒，通过 900 秒预算；实际 A7/A8 分别用 44.42/17.92 秒，单线程、主阶段峰值约 150 MB。两次求积检查另用 2.19/0.88 秒，总计约 65.4 CPU 秒。四项针对性测试通过；48→144 点求积最大 joint log score 差分别 1.16e−5、1.38e−7，均低于 1e−4 容差。
