## Diagnosis

1. Robust VEPM is a real numerical fix. It greatly reduces the variance blow-up caused by sparse-cell residual updates and makes the VEPM variance scale comparable to pooled-pre variance.

2. On `RZDT5_RR`, the fix translates into useful optimization performance. GPR-KG has the best native HV and IGD among the three methods in this pilot, and the common generic post-processing also gives GPR-KG the best HV and IGD, with only a small CVR cost.

3. On `RZDT2_VC`, robust VEPM improves the old auto-VEPM result but still does not close the oracle gap. The oracle-variance method remains much better, and pooled-pre is competitive after common post-processing. This suggests that the main limitation on `RZDT2_VC` is not only variance-scale explosion. It is likely a combination of weak variance-feature alignment, difficult feasible-boundary ranking, and mean-surrogate error near the chance-constraint boundary.

4. This is still a pilot (`n=3`, `N=80`). The conclusions should not be written as final statistical claims. They are sufficient for choosing the next engineering direction.

## Recommendation

- Keep robust VEPM as the default implementation safeguard. It is theoretically compatible with finite-sample variance estimation and prevents an implementation pathology.
- Do not claim that VEPM uniformly beats pooled variance. The correct claim is conditional: VEPM helps when variance calibration affects feasible-boundary decisions and the partition is aligned with the variance-driving features.
- For the next pilot, focus on `RZDT2_VC` boundary diagnosis: compare posterior feasible-boundary errors, mean-prediction errors near the boundary, and sampling allocation by variance region. If oracleV remains far ahead while robust VEPM is close to pooled-pre, the benchmark is still variance-critical but current VEPM is not extracting the variance structure well enough.
- For publication-scale runs, retain three reporting layers: native final recommendation, common offline post-processing, and variance/feasibility calibration diagnostics.

Interpretation:

1. The robust VEPM variance is no longer the dominant failure near the true boundary. For the near-boundary subset, GPR-KG's constraint-variance ratio is `0.9593`, essentially calibrated. This is a strong signal that the remaining `RZDT2_VC` gap is not caused by VEPM variance blow-up.

2. The remaining gap is mainly posterior chance-margin sign error. In the combined pool, GPR-KG still has many false positives and false negatives. The average false-positive point has positive true margin but negative posterior margin, while the average false-negative point has negative true margin but positive posterior margin. This is exactly a boundary-location error.

3. OracleV wins because perfect variance makes the chance margin sharper globally, not because it samples far more boundary points. Its observed near-boundary fraction is actually lower than GPR-KG's, but its combined-pool F1 is much higher.

4. The mid-`t1` region is pathological for all non-oracle methods: many true-infeasible mid-region points are accepted as posterior feasible. Low/high `t1` regions have the opposite issue, with many true-feasible points rejected. This pattern is consistent with a biased posterior constraint-mean surface interacting with the chance-margin correction.

Next engineering implication:

- Do not keep tuning VEPM alone for `RZDT2_VC`. The next useful enhancement should target boundary classification: either a theory-compatible boundary replication policy, a final conservative chance-margin calibration on held-out/posterior residuals, or a constraint-specific active learning step that samples points with small posterior chance margin and large posterior mean uncertainty.
- For the paper, this diagnosis supports a careful statement: robust VEPM fixes finite-sample variance instability, but variance calibration alone cannot guarantee improved optimization when the posterior mean of the constraint is biased near the chance boundary.
